# PRD — 自动刷新与抓取

## 一句话

插件自己每天在固定时刻检查两个游戏的卡池、名单与出图素材有没有更新，**有更新就自动拉取
并立即生效**——管理员部署之后不再需要定期手动跑 `tools/` 下的构建脚本，玩家也不用等
「管理员下次想起来」才能抽到新池。

## 背景

v0.3 之后，所有数据更新都靠管理员手动执行 `tools/build_data.py`（方舟）、
`tools/build_hsr_data.py`（星铁）、`tools/build_hsr_render_assets.py`（站点映射）。
新池上线到管理员跑脚本之间，插件一直用随包旧快照。`_conf_schema.json` 里预留的
`data_refresh_hours` / `prts_refresh_hours` 自 v0.1 起就 hint 明写「暂不生效」。

## 用户故事

1. 管理员装好插件就不管了。每天 04:00 与 12:00（时刻可配置），插件自动检查四样：
   方舟官方表（GitHub 条件请求快查）、PRTS 名单页（修订时间戳比对）、星铁卡池与名册
   （B站 wiki 全量比对）、星铁站点素材映射（JS 入口哈希比对）。
2. 检查发现更新 → 自动拉全量 → 校验 → 写盘 → **热重载**，下一个发指令的玩家用的就是
   新池；没更新 → 日志留一行，磁盘不动。
3. 新环境部署后，字体不再全靠内置兜底：fonts.json 里带 `url` 的字体（开源字体）启动后
   自动补齐；汉仪这类不可分发的字体留空由用户自备。
4. 上游挂了 / 被拦了：现有快照原样保留，插件照常可用，日志说明原因，下个检查点再试。
5. 官方发了新的交换所公告：limits.json 的估算与已抄录观测点随检查点自动重算，
   变了热重载降价表（解析公告流水线另立项）。

## 范围

**做**

- 每日定时检查，时刻进配置（`check_times`，默认 `04:00,12:00`，逗号分隔可多个）。
- 方舟官方表快查：条件请求，没变不下载正文；变了重建三份快照（卡池骨架、干员字典、
  名单）并热重载。
- 方舟 PRTS 廉价比对：页面修订时间戳，变了才抓页面重建名单。
- 星铁卡池与名册：全量抓取比对，有差异写盘并热重载。
- 星铁站点映射体检：站点 JS 入口哈希漂移检测，漂了自动重跑映射生成并让出图立即用上。
- limits.json 估算重算接入检查点，变了热重载降价表。
- 字体自动补齐：fonts.json 支持可选 `sources`（文件名 → 下载地址），缺文件自动下载，
  失败静默走链尾兜底。
- 全部抓取与重载失败只记日志，绝不影响现有数据与指令可用性。

**不做**

- limits.json 官方公告解析流水线（抓什么、在哪抓尚未调研，单独立项）。
- path_icons 再生成去 Chrome 硬编码（PNG 已随包，命途徽章已定稿）。
- 新干员立绘的调度下载（现有按需下载与预热机制已覆盖）。
- 失败推送通知（只记日志；插件没有可靠的主动推送渠道）。

## 验收标准

1. 把 `check_times` 配成下一分钟，插件到点自动跑完四项检查并留日志；抓取期间指令不卡。
2. 上游无变化时，两次检查之间不产生任何写盘（state 记录文件除外）。
3. 模拟上游变化后，插件自动拉取、写盘、热重载成功，新池立即出现在 `/卡池查询` 里。
4. 断网时检查只记日志，快照与 state 不动，抽卡指令照常。
5. 删掉随包字体再启动，带 `url` 的开源字体被自动补回；无 `url` 的（汉仪）跳过，
   出图走链尾兜底不崩。
6. 三个构建脚本的 CLI 行为（参数、退出码、输出语义）与 v0.3 完全一致。
7. 原有全部测试不改断言地通过；新逻辑有测试守着。

## 术语

沿用 `CONTEXT.md`：快照、名单快照、干员字典、预热、池型。新词：

- **检查点**（checkpoint）：一次定时触发里跑完的全部检查动作。
- **快查**（quick check）：不下载正文就能判断「上游变没变」的比对（条件请求、时间戳、
  哈希）。
