## 排序原则

用户 2026-11-15 定的四段顺序，从前往后不跳段（2026-11-19 追加的段 5 排在最后，同样只在
前一段退出条件达成后才开始）：

1. **先保证业务逻辑跑通、抽卡行为符合预期**
2. **再做图层渲染**
3. **接着加其他池子**
4. **最后补兑换等细枝末节**

理由（写下来防止以后又按编号顺序做回去）：

- 概率与名单错了，出图之后只会更难查：图片把数字藏起来，回归要连图一起重做。
  **先把「抽出来是谁」做对，再决定这张图上画什么。**
- 结果文案要标注的东西（选调生效、井赠送、契约变动）取决于玩法机制；渲染先做会被迫
  反复改版式。先把玩法字段定下来，渲染一次成型。
- 「按文件编号往下做」是旧习惯，不是要求。`issues/NN-*.md` 的 `NN` 只是**稳定标识**，
  改顺序不重编号，避免把已经提交的引用全改一遍。**执行顺序以本文件为准。**

### 2026-11-19 新增段 5：自选池

段 1–4 走完后，用户提出「适配中坚甄选及其他需自选干员的卡池」。这不是原四段里的尾巴，而是
一条独立需求：它要加**第 9 条指令**、一条**全局消息钩子**（多轮选人）、一张新表，以及引擎侧
**「星级内可出范围」**这个从前没有的概念。所以单列一段，不塞回段 3。

范围只做 `FESCLASSIC`（中坚甄选）与 `SPECIAL`（定向甄选）。`ATTAIN` / `CLASSIC_ATTAIN`
（跨年欢庆）**不是自选池**，是「首次 6★ 必为未拥有」，机制不同，见 issue 15 的 Comments。

**结案（2026-11-19，代码 `61e8113`）**：`games/arknights/choice.py`（范围/名额/份额/解析）+
`UpTargets.six_range`/`five_range` + `pool_choice` 表 + `/自选` 指令与全局钩子，579 条测试全绿。
范围与份额全部取自官方 `dynMeta.rarityPickCharDict` 与 `pool_rules.json::pick_by_rule_type`，
不依赖 PRTS 名单。端到端实测：400 次十连 105 个 6★，范围外 0 个，选中二人 55.2%（期望 50%）。

### 2026-11-18 调整：12 提前到段 3 之前

用户要求「提前 12，先跑通业务逻辑」。理由是真实环境里卡在更前面：没有 `_conf_schema.json`
时插件在面板里没有配置项，`enable_image` / `image_quality` / `allow_network` 只能靠改代码
默认值；也没有一条能自证「数据齐、指令齐」的命令。这些不解决，段 3 加的机制也没法验收。

做法：12 先做完，但**指令清单分期**——`games/arknights/help.py` 只声明当前已注册的指令，
`tools/selfcheck.py` 校验「帮助声明 == `main.py` 注册」双向一致，不写死 8/7。`/潜能仓库`（10）
与 `/契约兑换`（08）落地时各加一条，帮助与自检自动跟上。段 3 顺序不变。

### 2026-11-18 调整：段 3 内先做「标准池」（拆出 14）

用户要求「先做标准池」，即先做 R-05 的累计口径（`DOUBLE` / `CLASSIC` / `CLASSIC_DOUBLE`），
限时单 UP 池的「连续 150」（R-06）从 06 拆成 **issue 14**，排在 06 之后、09 之前。

理由是两条规则的口径相反却共用一张表：累计只增不减、锁过置位；连续会清零、提前抽到不算
生效。合在一个改动里最容易把「连续」写成「累计」，而这种错抽起来看不出、测起来也难补。
拆开后各自的验收只覆盖自己的口径，`up_miss_counter` 列在 06 一并建好，14 不再改表。
**编号仍是稳定标识，14 排在 06 之后执行，不代表它是这个项目最后一条。**

用户明确要求「**跳过 06-10，先把 R-11 做了**」。R-11 剩余 30% 那部分原本挂在 issue 07，
已提前拆成 issue 13 并做完；**07 的 Scope 相应减去「5 倍权重」一项**，只剩契约与 300 井。

## 各段的进入 / 退出条件

### 段 1 → 段 2

- 进入：数据骨架、经济、抽卡内核、水位分组、名单与 UP 规则均已落地。
- 退出（已达成）：`/单抽`、`/十连` 的文字链路端到端可跑；概率与名单逐条对齐官方；
  全量测试绿（286 条）；`/卡池查询` 能看到真池名、UP 名单与「往期 5 倍」。
- 附带的验收方式：大样本抽样核对各池型的 UP 占比（`tests/test_limited.py`、
  `tests/test_banners.py` 已把关键比例写成断言）。

### 段 2 → 段 3

- 进入：段 1 的文字结果结构稳定，不再改字段。
- 退出（已达成，2026-11-16）：单抽结果图与十连结果图可用；版式照游戏内（R-18），画面元素只用
  游戏素材，暗角/渐变/光晕/亮条由代码生成；**渲染在抽卡事务之外**，渲染抛异常时降级为文字
  结果并记警告日志（R-15），已入账的结果不回滚；立绘运行时下载并缓存、缺图占位不失败；
  单抽与十连的立绘比例同源。全量测试 332 条绿。
- 已定的事实（2026-11-16）：画布 1024×576；十连不显示干员名；单抽左文右图；字体待换，
  不作为段 2 的退出条件。

### 段 3 → 段 4

- 进入：出图稳定，结果文案有位置标注新增机制。
- 退出：选调两套口径（常驻累计 150/300、限时连续 150）、联动 120 抽保底、限定池契约
  与 300 井都生效，且各自有独立存档字段与回归用例。

### 段 4 收尾

- 契约兑换三档（75/200/300）、潜能仓库、帮助文案、配置项与自检脚本。
- 契约到期清零是刻意决策（PRD 已确认），不按官方 1:6 折算。
- **已达成（2026-11-19）**：三档按「75 = 当期 5★ UP、200 = 本系列已降价的往期、300 = 本期
  减去已降价」落地，200 档的降价日由 `tools/build_limits.py` 生成；`/潜能仓库` 按星级分页。
  全量 537 条测试绿，自检 `commands=8 tables=7 snapshot=ok`。

### 段 5 收尾

- 中坚甄选 / 定向甄选的**可出范围**进 `UpTargets`（`six_range` / `five_range`），范围与名额
  取自官方 `dynMeta.rarityPickCharDict`，份额取 `pool_rules.json::pick_by_rule_type`。
- 第 9 条指令 `/自选`：两段式（列候选 → 预览 → 确认落库），提交即锁定；附带一条严格限定的
  全局消息钩子，让「待选」状态下可以直接发 `2 9 13 14 15`。
- **已达成（2026-11-19）**：`games/arknights/choice.py` + `pool_choice` 表落地，端到端实测
  400 次十连抽样 105 个 6★、范围外 0 个、选中二人 55.2%（期望 50%）；全量 579 条测试绿，
  自检 `commands=9 tables=8 snapshot=ok`。
- `ATTAIN` / `CLASSIC_ATTAIN` 不在本段：它是「首次 6★ 必为未拥有」，需要玩家真实拥有表，
  另立 issue 前先定「已拥有」用哪份数据。
