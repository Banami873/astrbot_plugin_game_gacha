# PRD: 抽卡模拟器（明日方舟）

> Status: 需求已收敛（2026-11-15 拷问后），可进入 `to-spec`
> 更新于 2026-11-15

本文件的每条结论都来自 2026-11-15 的逐项确认，没有我替用户拍的部分。
出图版式已于 2026-11-16 定稿（照游戏内版式，见 SPEC R-18）；只剩「字体与游戏不符」待换

## Problem Statement

群里的博士想抽卡，但不舍得把合成玉砸进游戏；或者想验证「我到底还要多少抽才能出」，
而游戏内不给这类信息。现在群里要么没有抽卡玩法，要么用的实现有三类毛病：卡池编号会随
池子过期整体前移（记住的编号指向了另一个池，甚至把保底存档挂错池）、卡池数据链路一断
整个插件就不可用、保底水位不按池类继承导致「垫的水位」算不明白。

同时这是一次技术准备：将来要接《崩坏：星穹铁道》以及可能的其他游戏，抽卡内核不应该被
方舟的形状焊死。

## Solution

一个 AstrBot 插件。每天签到领 10 抽（新人首次使用送 30 抽），用 `/单抽`、`/十连` 在真实
卡池里抽，结果出图；记录潜能仓库、六星水位、每期选调累计与寻访数据契约。

抽卡规则按 PRTS 官方寻访规则保真：概率、水位继承、选调（150/300）、井（限定 300 / 联动 120）、
寻访数据契约兑换（75/200/300）都实现；不做参数模型与完整商城经济。

池子按**池名**指定，插件不显示任何编号。

## User Stories

资源与身份

1. 作为群成员，我想每天签到领 10 抽，以便有资源抽卡。
2. 作为群成员，我想同一天重复签到不重复发抽，以便规则公平。
3. 作为刚装上插件的新人，我想一次性领到 30 抽，以便立刻体验而不是等到第二天。
4. 作为群成员，我想我的抽数、水位、潜能只属于我自己，以便和别人互不干扰。

抽卡

5. 作为群成员，我想只打 `/单抽` 就默认抽当期限定池，以便少打字；限定池没开时直接告诉我，
   别偷偷改抽常驻。
6. 作为群成员，我想用 `限定 / 常驻 / 限时 / 中坚 / 联动` 指定池子大类，以便只想抽某类池。
7. 作为群成员，我想在当前大类有多个池时用池名前缀进一步指定（如 `/单抽 限时 海渊`），
   以便不会抽到隔壁池。
8. 作为群成员，我想在池名前缀匹配到多个池时被明确告知并要求补字，以便我不会靠猜。
9. 作为群成员，我想抽卡时看到剩余抽数被正确扣除，以便知道还能抽几次。
10. 作为群成员，我想抽数不足时被明确拒绝而不是抽出一半，以便不产生半截结果。
11. 作为群成员，我想看十连结果出图，以便在群里晒。
12. 作为群成员，我想即使出图失败也能拿到文字结果、且抽数与水位正常入账，以便不被渲染拖累。

规则保真

13. 作为玩家，我想六星基础概率为 2%、连续 50 抽未出后每抽递增 2%、第 99 抽必出，
    以便模拟结果与游戏一致。
14. 作为玩家，我想在标准寻访里垫的水位换池后仍然有效，以便能像游戏里那样提前垫水位。
15. 作为玩家，我想限定池与联动池的水位不跨期继承，以便不会误以为攒着能用。
16. 作为玩家，我想每个新池的前 10 抽必出 5★ 以上（每池一次），以便开池就有保底。
17. 作为玩家，我想常驻/中坚池累计 150 抽后下一次六星必为 UP、300 抽后必为另一名 UP，
    限时活动池连续 150 抽未出 UP 则下一次六星必为 UP，以便能用选调做规划。
18. 作为玩家，我想限定池累计 300 抽额外获得当期限定干员，以便复刻真实的「井」。
19. 作为玩家，我想联动池每 120 抽必得联动六星，以便判断还要不要继续抽。
20. 作为玩家，我想在限定池每抽获得 1 张寻访数据契约，并能用 75 / 200 / 300 张兑换
    当期限定 5★、解限满三年的旧限定 6★、当期限定 6★，以便攒到想要的干员。
21. 作为玩家，我想看到「距离必出还有多少抽」「本池已抽多少」「契约多少」，以便做决策。
22. 作为玩家，我想卡池结束后这期契约失效且界面提前提示，以便不会以为能留到下次。

存档

23. 作为群成员，我想看到自己已获得的干员与潜能数，以便知道重复抽到了谁。
24. 作为群成员，我想潜能数按重复次数累加，以便和游戏里的潜能一致。
25. 作为管理员，我想给指定成员增减抽数，以便能发奖或纠正。

卡池数据

26. 作为使用者，我想插件没网也能抽（用内置快照），以便不会因为网络问题完全不可用。
27. 作为使用者，我想官方出新池后插件能自动更新卡池，以便不用手动维护。
28. 作为使用者，我想看到当前进行中的池子、UP 干员、起止时间，以便决定抽哪个。

## Functional Scope

- [ ] `/抽卡帮助`
- [ ] `/抽卡签到`：每日 +10，同日重复不发
- [ ] `/单抽[池类][池名]`：扣 1 抽
- [ ] `/十连[池类][池名]`：扣 10 抽
- [ ] `/卡池查询`：进行中卡池、UP 名单、起止时间；已结束的池可查但不能抽
- [ ] 卡池数据保留全部历史池（供查询与将来回溯），抽卡只接受进行中的池
- [ ] `/潜能仓库`：已获干员与潜能，按星级分页
- [ ] `/契约兑换 <75|200|300> [目标]`：寻访数据契约兑换（写 Spec 时发现缺入口，补列）
- [ ] `/抽数修改`：管理员限定，支持 @ 指定成员
- [ ] 概率保真：基础 2/8/50/40、六星 50 抽后递增、99 抽硬保
- [ ] 水位按池类分组继承：标准寻访跨池永续、中坚独立永续、限定/联动/跨年池内清零
- [ ] 新池前 10 抽必出 5★ 以上（每池一次）
- [ ] 选调：常驻/中坚累计 150 与 300 两档定向；限时活动池「连续 150 抽未出 UP」定向
- [ ] 限定池：每抽 1 张寻访数据契约；累计 300 抽赠送当期限定
- [ ] 契约兑换：75（当期 5★）/ 200（解限满三年旧 6★）/ 300（当期 6★）；池结束剩余契约作废
- [ ] 联动池：每 120 抽必得联动六星
- [ ] 池子按池名/类别指定，界面不出现编号
- [ ] 不带类别时只抽限定；限定池没开就明确报错，**不退化**到常驻
- [ ] 图片渲染：单抽结果图 + 十连结果图，照游戏内寻访结果界面的版式
- [ ] 卡池数据：官方 `gacha_table.json`（骨架 + 机制参数）与 PRTS「卡池一览」（池名 + UP 名单）
      双源合并，内置快照兜底。**官方表单独不可用**，原因见 `Further Notes` 的数据源更正
- [ ] 多用户数据隔离

## Out of Scope

- **《崩坏：星穹铁道》** —— 缓一期，方舟验收后再评估；core 只做模糊预留，不定义游戏接口
- 寻访参数模型与契约交换所的完整商城经济（只做 75/200/300 三档兑换；剩余契约池结束作废，
  不折算成参数模型——这是对官方的刻意简化）
- 合成玉 / 源石 / 凭证商店 / 采购中心
- 公开招募（recruit）标签与计时模拟
- 关卡掉落、皮肤、基建
- 已上线的 `/单抽awa`、`/十连awa` 调试后门（会让任何人都能无限白抽）
- 群聊限速与防刷屏（后续可加，本期不做）
- **历史池回溯抽卡**：预留位置，本期不做。数据层保留全部池（460 个）以便查询与将来实现，
  抽卡入口只接受进行中的池；将来若做，语义必须是独立沙盒（不计水位、不产契约）
- **归航寻访（`BACKFLOW`）与新人寻访**：面向回归 / 新手玩家的定向池，不是所有人都能抽，
  本期不实现。这两个池型在解析阶段直接丢弃，不进卡池列表；归航寻访的官方 `endTime`
  是 2030 年的占位值，按时间判活动会得到一个永远开着的假池（详见 SPEC R-12b）

## Acceptance Criteria

1. 未触发保底时，十万次抽取的六星频率落在 2% ± 0.2% 内。
2. 标准寻访连续 99 抽内必出六星；出一张六星后计数归零。
3. 标准寻访垫到第 60 抽时切换另一个标准池，「距离必出」计数保持不变；切到限定池则从 0 开始。
4. 同一池内前 10 抽至少出现一张 5★ 以上；该池第二期不重复触发。
5. 常驻/中坚池累计满 150 抽后，下一次六星必定是当期 UP 干员；满 300 抽后必定是另一名 UP。
   限时活动池连续 150 抽未出 UP 时，下一次六星必定是该 UP。
6. 限定池累计 300 抽时，用户拿到当期限定干员，且该次不消耗水位。
7. 联动池第 120 抽必得联动六星，提前抽到时计数清零。
8. 限定池抽 30 抽后有 30 张契约，可用 75 档兑换当期 5★（不足时明确拒绝）；池结束后契约归零，
   兑换入口关闭。
9. 池子只能用池名或类别指定；输入 `3` 之类的裸数字不会命中任何池。
10. 关闭网络后仍能启动并抽卡（走快照）；恢复网络且官方表有更新时，卡池数据被重建。
11. 出图失败时，用户仍收到文字结果，抽数扣除与水位推进照常。
12. 签到同一天第二次调用不增加抽数；跨天恢复 +10。
13. 两个用户在同一群的抽数、水位、潜能互不可见、互不影响。

## Further Notes

### 数据源更正（2026-11-15，写 SPEC 时推翻原决策）

原第 3 项决策「官方 `gacha_table.json` 为唯一自动源，不解析 PRTS」**基于错误前提**，现更正：

实测官方表（`Kengxxiao/ArknightsGameData`，460 池）里，近 400 天的 86 个池有 **62 个池名是
占位串**「适合多种场合的强力干员」，`SINGLE`/`DOUBLE`/`NORMAL` 的 `gachaPoolDetail` 全是
`-`，`dynMeta` 只对中坚/定向甄选/跨年/归航等少数类型有值，`LIMITED`/`LINKAGE` 连 UP 名单
都没有（只有 `limitedCharId` 与 `linkageParam`）。**官方表能给出机制参数，给不出「谁在 UP」。**

更正为：官方表提供骨架（池 id、规则类型、起止、保底参数、井参数），PRTS「卡池一览」提供
池名与 UP 名单，两源按起止时间对齐，内置快照兜底。详见 `SPEC.md` 的 R-14。**用户已确认**。

### 已解决的争议（留档）

- **池编号**：确定取消编号、按池名指定。原方案的「编号单调递增不复用」被否，因为它只是把
  空洞暴露给用户；按池名指定从根上取消了「编号指向另一个池」这一整类问题。
- **水位**：否掉参考插件的「全局一对计数器」，改为按池类分组。参考插件 `pool_rules.json`
  里的 `counter_inherit` 字段从未被读取，属实现缺漏。
- **抽卡规则**：否掉「只保真概率层」，也否掉「连参数模型一起做」。取中间的「计数 + 必得 +
  75/200/300 契约兑换」。
- **渲染素材**：游戏 UI 贴图随包分发（与参考插件一致），README 声明版权归鹰角、同人非商业。
  立绘不进包（318 人两张一套体积太大），运行时下载并缓存；下载不到就画占位，不能让抽卡失败。
- **分层**：core 只放游戏无关件，方舟规则/渲染/文案沉到 `games/arknights/`；**不定义游戏接口
  Protocol**，等星铁真做时再提炼。
- **星铁**：本期不做。`starrail-data` 为 MIT 纯 JSON 无图，Web API 已 404，卡池表需另找来源。

### Input for Spec（技术倾向，不是契约）

- 概率模型沿用「权重上限 10000 的轮盘 + 溢出时从低星往上裁剪」，已核对与官方公示一致。
- 渲染沿用「元素表 + 绘制」两层，改版式只改元素表。
- 池型规则、pity 分组、选调/井阈值全部外置 JSON。
- 概率引擎是纯函数，适合先写测试（统计断言 + 保底边界断言）。

### 未定

- **两个视觉缺陷的验收基准**：**已结案（2026-11-16）**。十连立绘偏大 → 不再是问题：版式
  改成游戏内的一排压叠竖卡，立绘比例由游戏参数表统一（立绘宽 = 卡宽 1.35 倍、裁切在卡内，
  单抽与十连同源）。单抽字体与游戏不符 → **仍然存在**，用户说「先这样，等我找到字体再改」，
  因此本期只保证中文不缺字、不溢出，不做像素级对齐。
- **契约到期**：官方是折算成寻访参数模型（1:6，永久），PRD 原写「清零」是基于我说错的前提。
  已在 SPEC 阶段提出并确认：**仍然选择清零**，不折算、不留余额、不做参数模型交换所。属刻意
  简化，不是对官方的实现对齐。
- **「卫戍」属于哪类池**：官方 13 个 `gachaRuleType` 里没有这个类型，怀疑是具体池名。
  **已结案（2026-11-15）**：卫戍寻访 = `GACHAWITHSPECIFIED6`，官方表 `gachaPoolId = NORM_79_0_3`，
  池内 6★ 只有公告列的 10 名、均分，属**标准寻访**（水位进标准组）。
- **`NORMAL`（联合行动）有无 150 定向选调**：PRTS 未提，SPEC 暂按无选调处理。
  **已结案（2026-11-15）**：用户确认卫戍、联合行动、定向甄选均无选调。
