## Background

契约如果只能攒不能花，限定池的经济就是死的。SPEC R-09 定了三档：75 换当期 5★ UP、200 换
解限满 3 年（春节系列 4 年）的旧限定 6★、300 换本期可兑换的 6★。PRD 原功能清单漏了这条
指令，SPEC 阶段补成第 8 条。

## Goal

`/契约兑换 <75|200|300> [目标]` 能用契约换到干员并正确扣减；不足时明确拒绝；池结束后入口
关闭；目标不在名单时列出可选。

## Scope

- `main.py` 注册 `/契约兑换`
- 75 档：目标固定为当期 5★ UP，不要求指定
- 200 档：候选来自 `limits.json` 里 `discount_from <= now` 的旧限定；要求指定目标
- 300 档：候选为本期 UP 名单里的 6★，要求指定目标（单人时可不指定）
- 扣减与入库同一事务；兑换不推进水位、不产契约
- 不做：寻访参数模型、凭证商店

## Acceptance criteria

- [x] 契约 30 时 `/契约兑换 75` 被拒并回报「需要 75 张，你有 30 张」
- [x] 契约 75 时兑换成功，5★ UP 入库，契约归零
- [x] `/契约兑换 300` 未指定目标且候选有多人时列出候选、不扣契约
- [x] 200 档只列出 `discount_from` 已到期的干员，早于到期日的不出现
- [x] 已结束池的兑换请求被拒
- [x] 兑换后 `inventory.count` 正常累加（重复兑换同一人 → 潜能提升）

## Comments

200 档是**显式表**而非公式推导：官方两期公告的边界互相矛盾（同样「不满 4 年」，百炼嘉维尔
已在 200 档、缄默德克萨斯仍在 300 档），说明官方逐期逐个点名，没有统一偏移量。故
`limits.json` 里公告能确认的写精确日期，其余按庆典/夏季 +4 年、春节 +5 年估算并带
`estimated: true`，兑换界面在估算项上标注。若要全精确，需新增「解析官方公告交换所名单」
的数据流水线，兑换层不用改。详见 SPEC R-09 与 Open Question 1。

**结案（2026-11-19，代码 `1f3fdd6`）**

- 真实数据实测：把「将雪投火」结束时间推到 2100 年造一个进行中的庆典池，契约 400。
  - `/契约兑换 75` → 直接换「奥尔佳」，契约 400 → 325；
  - `/契约兑换 200` → 候选 6 名（W / 迷迭香 / 浊心斯卡蒂 / 耀骑士临光 / 归溟幽灵鲨 /
    缄默德克萨斯）；
  - `/契约兑换 300` → 候选 8 名（当期 塔露拉 / 冻河 + 往期 维什戴尔 / 荒芜拉普兰德 /
    新约能天使 / 凛御银灰 / 塑心 / 缪尔赛思），与 200 档零重叠——正好复现官方
    2026-05-01 庆典「300 档当期 2 + 往期 6、200 档 5 名、两组不重叠」的结构。
- **两条口径是实测出来的，原 Scope 没写**：
  1. 200 档**按系列筛**：庆典交换所的 200 档只有庆典限定，夏季的要等到夏季交换所才有，
     春节限定从不出现在庆典交换所。不筛会让年、夕混进庆典池的兑换名单。
  2. 300 档**排除已进 200 档的人**：否则同一期同一人会出现两个价格。
- `limits.json` 由 `tools/build_limits.py` 生成而不是手写：4/5 年估算 + `ANNOUNCED` 里两期
  公告的观测点修正（公告列进 200 档的往前拉、仍留 300 档的往后推）。27 条里 12 条被点名过
  （`estimated: false`）。`--check` 只比对不写盘，`TestLimitsTableIsInSync` 把「快照更新后
  忘了重跑」变成红灯。
- 扣减用 `UPDATE ... WHERE contracts >= cost` 一次完成判定与扣减；兑换只写
  `limited_state.contracts` 与 `inventory`，水位与 `pool_state` 一律不动。
