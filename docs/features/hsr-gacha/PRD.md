# PRD — 星穹铁道抽卡

## 一句话

在同一个插件里，让玩家能用 `/星铁十连` 抽星穹铁道的**角色活动、光锥活动、群星（常驻）与
联动**四类跃迁，规则与真游戏一致：结果发回文字与结果图——十连把十张卡按站点版式拼成
1920×1080，单抽走站点的满屏立绘大图。这是第二个游戏，目的不只是"能抽"，更是把
"加一个游戏＝加一个目录"这件事从口号变成事实。

## 背景

上一轮（v0.2）把方舟的规则从 `core/` 清出去，内核只剩与游戏无关的件（概率数学、池骨架、
通用表与事务）。当时没定游戏接口，理由是"没有第二个实现，定形就是猜"。现在补第二个实现，
顺便把接口定下来。

第一版只做了角色活动跃迁；这一轮把另外三类补齐，并把"同时开着好几张池时抽哪张"定成规则。

## 用户故事

1. 玩家发 `/星铁十连`，抽本期新角色池：十件结果（角色或光锥）、星级统计、距 5★ 保底还差多少抽。
   十连**另有一张结果图**：逐条复刻 `hsr.wishsimulator.app` 的结果页——十张横卡
   按 3/4/3 斜阵摆好，一眼看出出了几个金。图发出来后仍跟一行文字简报（剩余抽数 + 距硬保底）。
   单抽也出图，但走站点的单抽分支：立绘大图居中 + 左侧信息条，不是十连阵的一张卡。
2. 玩家想抽复刻角色，发 `/星铁十连 火花`；想抽光锥，发 `/星铁十连 光锥`；想抽常驻，
   发 `/星铁十连 群星跃迁`；想抽联动，发 `/星铁十连 Saber`。
3. 玩家发 `/星铁卡池`，看到现在能抽的全部池：池型、名字、UP 名单、起止或「长期开放」。
4. 玩家发 `/星铁签到`，每天领固定抽数；第一次使用有新人礼。
5. 管理员发 `/星铁抽数修改 @某人 100` 给人补抽数。
6. 群里两个游戏都有人玩时，`/单抽` 仍是方舟，`/星铁单抽` 是星铁，互不干扰。

## 范围

**做**

- 角色活动跃迁：5★ 0.6% / 74 抽起陡升 / 90 抽硬保底 / 50% UP；4★ 5.1% / 10 抽必出 / 50% UP。
- 光锥活动跃迁：5★ 0.8% / 66 抽起陡升 / 80 抽硬保底 / 75% UP；4★ 6.6% / 10 抽必出 / 75% UP。
- 群星跃迁（常驻）：5★ 0.6% / 90 抽，**角色与光锥各半、没有 UP**；4★ 同理；3★ 全是光锥。
- 联动跃迁：角色与光锥两套，规则同对应的活动跃迁，**保底单独一条、4★ 没有 UP**。
- 三 UP 的复刻合集（铭心之萃 / 真意之汇）拆成三张单 UP 池，与游戏里一致。
- 水位按池型分桶：角色 / 光锥 / 联动角色 / 联动光锥 / 常驻，同类型跨期继承，不同类型互不影响。
- 抽数与仓库独立于方舟（各一个库）。
- **四类池十连与单抽出结果图**：十连各出一张 1920×1080 的图，版式照
  `hsr.wishsimulator.app` 的结果页逐条复刻（3/4/3 斜阵、横卡、稀有度底色与星级、属性图标/
  命途图标）；单抽照该站点的另一条分支画满屏立绘大图 + 30% 宽信息条。
  卡面与取景表直接取该站点现网产物（不是源码仓库镜像），不自行设计版面。
  角色池的三星位本来就是光锥，按站点的 `.lightcone` 卡画。
- **4★ 跨类型**：官方允许角色池的 4★ 位出光锥、光锥池的 4★ 位出角色，本插件照做；
  UP 份额仍是角色池 50% / 光锥池 75%。
- **星缘相邀**：玩家从 13 位 5★ 角色里选 7 位，作为角色活动/联动跃迁 5★ 歪掉的候选；
  群星跃迁的可抽名单不受影响。
- **群星跃迁 300 抽自选**：累计满 300 抽可任选 1 位常驻 5★ 角色，一次性、不消耗抽数。
- **星芒/余烬与星魂叠影**：抽卡按官方副产物表发星芒/余烬，可换抽数与常驻光锥；
  重复角色/光锥的星魂（E1–E6）/叠影（S1–S5）按仓库份数展示。

**不做**

- 始发跃迁（新手池）：只能十连、8 折、50 抽上限，要一条终身计数与折扣计费，单独一轮再做。
- 抽卡历史记录（只记水位与仓库）。
- 星缘相邀的另一种配法（把本期 UP 也选进星缘，官方 UP 占 62.5%；本实现按 57.1%）。
- 星芒换「命运的足迹」、4★ 角色每月轮换商品、星魂溢出后的旅伴银灵兑换。

## 验收标准

1. 四类池都能抽：结果条数等于抽数，仓库按份数累加，标题带池型。
2. 角色池第 90 抽必出 5★、光锥池第 80 抽必出 5★；歪了一次之后同星级下次必中（群星除外，它没有 UP）。
3. 光锥池抽出来的每一件都是光锥；群星池的 5★ 角色与光锥大约各半。
4. 抽光锥池不影响角色池的水位，联动池也不影响活动池。
5. 10 万抽：角色池 5★ ∈ [1.4, 1.8]%、光锥池 5★ ∈ [1.6, 2.2]%。
6. 不带词只抽**当期限定**（`/星铁十连` ≡ `/星铁十连 限定`）；第一个词写类别
   （复刻 / 光锥 / 联动 / 常驻）就只在该类里找；只写名字时先看限定、再看全部在开池
   （`/星铁十连 Saber`、`/星铁十连 银狼` 都能抽）；限定没开时 `/星铁十连` 报错，
   **不退化**成常驻或复刻。
7. 方舟原有 9 条指令行为与文案一字不变，原有测试断言一条不改。
8. 数据抓取失败时插件照常启动，`/星铁十连` 回一句明确的"数据没装载"，不是抛异常。
9. 四类池的十连都出一张 1920×1080 的图（JPEG），版式与 `hsr.wishsimulator.app` 结果页一致：
   十张卡按 3/4/3 三排、整块左倾 13°，卡内人物反向转正；发图后仍跟一行
   「剩余 N 抽 · 距 5★ 硬保底还有 M 抽」。
10. 某张立绘下载不到时，那张卡画占位（底色 + 星级 + 名字），**其余九张照常出图**；
    整体渲染失败（缺字体 / 缺 PIL / 坐标算错）时退回原来的完整文字，抽数与水位不受影响。
11. 光锥池十连出同样的 1920×1080 结果图，卡面为光锥插画、命途图标与 LIGHTCONE 标签；
    单抽也出 1920×1080 结果图，但走 `WarpResult.svelte` 的立绘大图分支（角色满屏居中、
    光锥 35vh 转 8°、左侧 30% 信息条），不是十连阵的一张卡。
12. 角色池的 4★ 位会出 4★ 光锥，光锥池的 4★ 位会出 4★ 角色；4★ UP 份额分别保持
    50% / 75%，大保底仍必中本期同类 UP。
13. `/星铁星缘相邀` 能从 13 位候选里选 7 位；选完后角色活动/联动池歪出的 5★ 落在这
    7 位里，群星跃迁仍只抽 7 位常驻角色。`/星铁星缘相邀 重置` 恢复默认。
14. `/星铁常驻自选` 显示群星累计 N/300；满 300 可领 1 位常驻 5★ 角色，领取后入仓库、
    不能重复领，也不扣抽数。
15. 重复角色按仓库份数给星魂（上限 E6）与星芒（5★ 40 / 4★ 8；第 8 次起 100 / 20），
    重复光锥给叠影（上限 S5）或星芒/余烬；20 星芒或 90 余烬可换 1 抽（余烬每月限 5），
    600 星芒可换常驻 5★ 光锥（每月 1 次），`/星铁仓库` 能看到这些阶数与余额。

## 术语

沿用 `CONTEXT.md`：**水位**（连续未出最高星级的次数）、**UP**（本期出率提升）、
**大保底**（歪过一次之后的下一次必中）。星铁的"跃迁"在本插件里统一叫**卡池**，
与方舟一致，避免两套名词；池型内部仍用官方叫法（角色活动 / 光锥活动 / 群星 / 联动）。
